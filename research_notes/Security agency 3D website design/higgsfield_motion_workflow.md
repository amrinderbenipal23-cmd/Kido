## KQ1. What exactly can Higgsfield generate today (image, video, 3D, audio, website builder) and what are the key model names and presets?

### Takeaway
Higgsfield is a multi-model aggregator plus a set of in-house models: Soul 2.0 / Soul Cinema (images), Cinema Studio 3.0/3.5/4.0 and the DoP preset engine (video), Genjutsu (motion transfer / object replacement), Marketing Studio "Motion" presets (2D/SaaS/"hypermotion" brand motion), Vibe Motion (code-based motion graphics, Feb 2026), image-to-3D GLB via Meshy/Tripo/Hunyuan/SAM-3, audio/voice/lipsync (Intone, Speak), and a first-party website/app/game builder exposed over MCP (Cloudflare Worker, React 19 + TanStack Start, with a `scroll-scrub` animated-website template).

## KQ2. Which camera-motion presets exist, and which are best for a looping hero background and for a "compass / find your north" motif?

### Takeaway

### Inferences
- **Looping hero background**: use 360 Orbit or 3D Rotation on a centered object (e.g. a brass compass, a guard's badge, a radar dish) on charcoal/navy; a full 360° orbit returns to its start pose and is the only preset that is intrinsically loopable. Dolly In / Crane Up are not loopable and should be used as scroll-scrubbed (non-looping) films, or looped with a crossfade.
- **Compass / "find your north" motif**: 360 Orbit (camera revolves around the compass while the needle settles north) or 3D Rotation (the compass itself rotates) are the best preset fits; Crane Up / Dolly Out can reveal a map or city beneath it for a "guided from above" beat. Avoid Crash Zoom/Bullet Time for a corporate-security tone; FPV Drone suits a perimeter/facility fly-through section rather than a hero loop.
- Preset names are consistent across sources at the core set, but counts (20+ / 50+ / 70+) vary by source and by underlying model (DoP vs WAN vs Kling); verify in-app.

## KQ3. What do YouTube tutorials about Higgsfield + website design recommend step by step? (≥5 videos with URLs)

Framer users drop the MP4 directly on the canvas as a native video element.

## KQ4. What file formats/sizes does Higgsfield export, and how should they be optimized for web (ffmpeg for WebM/MP4 loops, poster frames)?

### Takeaway
Higgsfield delivers H.264 MP4 (preview CDN files are `*-h264-600-v1.mp4`; WebP thumbnails); practical generation ceiling is 1080p for most models with 4k on Cinema Studio 3.0 / Seedance 2.x / FLUX 3 / Kling Omni, durations 4–15 s (Cinema Studio 3.0) or longer on third-party models, aspect ratios 21:9 → 9:16. Higgsfield's own web recipe: re-encode to H.264 yuv420p, CRF ~20, GOP 8 (desktop) / 720p CRF 23 GOP 4 (mobile), `-sc_threshold 0`, `-an`, `+faststart`, and extract the poster from the encoded clip's first frame; third-party guides add a VP9 WebM variant (`-c:v libvpx-vp9 -crf 35 -b:v 0 -an`) and a crossfade to hide loop seams.

### Cited Findings
- **Export resolution**: Higgsfield 2.0 topped out at 720p on Free and 1080p on paid plans, with no native 4K; third-party tools suggested for 4K — [flowith FAQ](https://flowith.io/blog/higgsfield-2-0-faq-video-length-skin-rendering-commercial-rights) (via search snippet). Sozee describes output as "typically 720p, with some 1080p presets" — [sozee.ai](https://www.sozee.ai/resources/?p=15003) (via search snippet). The MCP catalog now shows 4k on `cinematic_studio_3_0`, `seedance_2_0`, `seedance_2_5`, `flux_3_video`, `gemini_omni_flash_*`; Seedance 2.5 on Higgsfield is listed by a third party at 480p/720p, 4–30 s, 7 aspect ratios — [aivideosensei Seedance 2.5 settings](https://aivideosensei.com/guides/seedance-2-5-higgsfield-settings) (via search snippet).
- **Upscaling**: Higgsfield's AI Video Upscaler page says you can upscale to 1080p, 2K or 4K — [higgsfield.ai/sora-2-upscale](https://higgsfield.ai/sora-2-upscale) (via search snippet); MCP has `topaz_video` (1080p/2160p), `bytedance_video_upscale` (1080p/2k/4k), `video_upscale`, `fps_boost`.
- **Aspect ratios / durations**: Creator Hub changelog lists 720p or 1080p and aspect ratios "from 21:9 to 9:16" and "3 to 30 seconds" of output (model-dependent) — [Higgsfield changelog](https://higgsfield.ai/changelog) (via search snippet; conflicts with flowith's 16:9/9:16/1:1/2.39:1 list). MCP `cinematic_studio_3_0`: 4–15 s, auto/21:9/16:9/4:3/1:1/3:4/9:16, 480p/720p/1080p/4k (read directly).
- **Container/codec evidence**: Higgsfield's own CDN preset previews are H.264 MP4s named `…-h264-600-v1.mp4` with `.webp` thumbnails (read directly from `get_presets` output URLs on cdn.higgsfield.ai / cloudfront). A Framer user's 6-second hero clip was 6.8 MB — [tarasovs.me](https://tarasovs.me/higgsfield-claude-framer-ai-video/) (via search snippet). None of the fetched sources show Higgsfield exporting WebM natively.
- **Official Higgsfield encode recipe** (read directly from `references/scroll-scrub-asset-video.md`, the helper shipped inside Higgsfield's website-builder skill):
  ```bash
  # desktop: native res, H.264 yuv420p, CRF 20, GOP 8, no scene-cut keyframes, audio stripped, faststart
  ffmpeg -v error -y -i in.mp4 -an -vf "unsharp=5:5:0.8:5:5:0.0" \
    -c:v libx264 -preset slow -crf 20 -pix_fmt yuv420p \
    -g 8 -keyint_min 8 -sc_threshold 0 -movflags +faststart out.mp4
  # mobile: cap height 720, CRF 23, GOP 4
  ffmpeg -v error -y -i in.mp4 -an -vf "scale=-2:'min(720,ih)',unsharp=5:5:0.6:5:5:0.0" \
    -c:v libx264 -preset slow -crf 23 -pix_fmt yuv420p \
    -g 4 -keyint_min 4 -sc_threshold 0 -movflags +faststart out-mobile.mp4
  # poster = exact first frame of the ENCODED clip
  ffmpeg -v error -y -ss 0 -i out.mp4 -frames:v 1 -q:v 2 poster.png
  # exact last frame (for seam handoff to the next leg)
  ffmpeg -v error -y -i out.mp4 -vf reverse -frames:v 1 -q:v 2 last.png
  ```
  Rules stated with it: "Every poster is the exact first frame of the clip beside it"; "Provide mobilePoster whenever mobileClip is set"; byte budget ≤32 MiB desktop / ≤16 MiB mobile for all clips; "Visited clips are retained for smooth reverse scroll, so oversized clips cost memory too"; keep raw clips out of `public/`.
- **Community frame-sequence recipe**: ffmpeg splits each clip into ~180 JPGs, compressed to 1600 px wide, quality 88 — [GitHub scroll-cinematic-claude](https://github.com/zubair-trabzada/scroll-cinematic-claude).
- **WebM/VP9 for background loops**: `ffmpeg -i input.mp4 -c:v libvpx-vp9 -crf 35 -b:v 0 -an`, and put the WebM `<source>` first in the `<video>` tag — [salivity WebM loop guide](https://salivity.github.io/webm/article/how-to-create-a-seamless-webm-loop-with-ffmpeg) (via search snippet).
- **Seamless loop via crossfade**: blend the last and first frames so the loop transition is invisible; loop length ≈ 2×input_duration − 2×crossfade_duration — [skills.sh video-loop](https://skills.sh/coroboros/agent-skills/video-loop); [convertintomp4 how to loop video](https://convertintomp4.com/blog/how-to-loop-video); [magichour seamless loops](https://magichour.ai/blog/how-to-make-seamless-ai-video-loops) (via search snippets).
- **HTML**: `<video autoplay muted loop playsinline>` with `poster`; Lighthouse flags `<video>` lacking captions — [damieng HTML5 video cheatsheet](https://damieng.com/blog/2025/html5-video-cheatsheet/); [tarasovs.me](https://tarasovs.me/higgsfield-claude-framer-ai-video/) (via search snippets).

### Inferences
- A working two-format pipeline for a security-agency hero: generate 16:9 at 1080p (or 21:9 for an ultrawide hero), `-an`, then (a) autoplay-loop variant: VP9 WebM CRF ~33–35 + H.264 MP4 CRF ~22 fallback, poster PNG/WebP from frame 0, 6–10 s, target <4–6 MB; (b) scroll-scrub variant: Higgsfield's GOP-8/CRF-20 H.264 recipe (seek accuracy matters more than size), mobile GOP-4 720p variant, and a `blob:` CSP entry if using blob-backed seeking.
- Because Higgsfield's own skill forbids on-screen text in footage, headlines like "Find your north" should be HTML/GSAP overlays, not generated into the video.

### Gaps
- No official Higgsfield documentation of exact export codec/bitrate/fps was retrievable (changelog and help center blocked); the H.264 inference rests on CDN file naming and third-party reports.
- Native frame rate of Higgsfield outputs not confirmed (one skill targets 30 fps; model-dependent).
